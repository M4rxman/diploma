Огляд проекту

Цей 3D action game демонструє сучасні концепції розробки ігор з використанням Godot Engine. Проект включає складні системи ШІ, процедурну генерацію контенту та надійне управління станом гри.

Ключові особливості

  • Динамічна генерація рівнів - Процедурне створення контенту з навігаційними мешами
  • ШІ-керовані вороги - Складна поведінка ворогів з хвильовим спавном
  • Система збереження/завантаження - Надійне управління станом гри
  • Фізичний бій - Реалістичний рух гравця та бойова механіка
  • Автоматизоване тестування - Фреймворк GUT для забезпечення якості коду

Технічні характеристики

Характеристика Значення
Рушій Godot Engine 4.2.1
Мова програмування GDScript

GameManager API

Примітка: GameManager служить центральним координатором для всіх основних ігрових систем.

Огляд класу

class_name GameManager extends Node3D # Центральна система управління грою, яка координує # стан гравця, ШІ ворогів, генерацію рівнів, управління камерою # та операції збереження/завантаження.

Основні властивості

player: Node
Посилання на вузол персонажа гравця. Автоматично призначається через анотацію @onready.
save_manager: SaveManager
Посилання на систему управління збереженням/завантаженням.
level_manager: DynamicLevelManager
Посилання на систему генерації та управління рівнями.

Ключові методи

setup_camera()

Налаштовує камеру на правильну позицію та кут.

Скидає камеру до належного ізометричного вигляду з позицією (0, 20, 6), дивлячись на початок світових координат.

Деталі реалізації:

  • Позиція: Vector3(0, 20, 6)
  • Ціль: Vector3(0, 0, 0)
  • FOV: 60.0 градусів
handle_mouse_cursor()

Обробляє поворот гравця на основі позиції курсора миші.

Використовує кастинг променів камери для визначення того, куди вказує миша у 3D просторі, та повертає гравця, щоб дивитися в цю позицію.

Попередження: Цей метод автоматично викликається з _physics_process() і не повинен викликатися вручну.
start_new_game()

Ініціалізує нову ігрову сесію.

Скидає стан гри, статистики гравця та позиціонує гравця в центрі згенерованого рівня.

Скидає:

  • current_wave = 0
  • game_started = true
  • level_completed = false
  • Здоров'я гравця до max_health
  • Боєприпаси гравця до max_ammo
_turn_on_enemy_ai() -> bool

Вмикає ШІ для всіх ворогів.

Повертає: true якщо ШІ всіх ворогів успішно увімкнено, false інакше

# Приклад використання var ai_enabled = game_manager._turn_on_enemy_ai() if not ai_enabled: print("Деякі вороги не змогли увімкнути ШІ")

Сигнали

wave_changed(wave_number: int)
Випускається при початку нової хвилі ворогів.
level_completed_signal
Випускається при завершенні всіх хвиль поточного рівня.

LevelSpawner API

Примітка: LevelSpawner управляє хвильовим спавном ворогів з прогресивним збільшенням складності.

Огляд класу

class_name LevelSpawner extends Node3D # Система спавну рівня для ворогів та припасів, яка управляє # хвильовим спавном ворогів з прогресивною складністю, # скиданням припасів та виявленням завершення рівня.

Експортовані властивості

enemy_scene: PackedScene
Шаблон сцени для спавну ворогів. Усі створені вороги будуть екземплярами цієї сцени.
За замовчуванням: preload("res://scenes/generic_enemy.tscn")
supplies_scene: PackedScene
Шаблон сцени для спавну ящиків з припасами під час прогресу хвиль.
За замовчуванням: preload("res://item/Supplies.tscn")

Ключові методи

reset()

Скидає спавнер для нового рівня.

Очищує весь поточний стан спавну, видаляє існуючих ворогів та припаси, і готує спавнер для свіжого рівня.

Процес:

  1. Зупиняє поточний таймер спавну
  2. Скидає всі змінні стану до значень за замовчуванням
  3. Видаляє всіх існуючих ворогів з групи "enemies"
  4. Видаляє всі існуючі припаси з групи "supplies"
  5. Чекає один кадр для очищення
  6. Ініціалізує хвилі для нового рівня
initialize_waves() -> bool

Знаходить та ініціалізує хвилі з навігаційної карти.

Повертає: true якщо хвилі успішно ініціалізовано, false якщо налаштування не вдалося

Створює конфігурації хвиль з прогресивним масштабуванням складності. Кожна хвиля має збільшену кількість ворогів, здоров'я, шкоду та швидкість.

spawn_supplies_near_player()

Створює припаси поблизу гравця на рівні землі.

Створює скидання припасів в околицях персонажа гравця. Використовує фізичний рейкастинг для забезпечення приземлення припасів на твердій землі.

Параметри спавну:

  • Відстань від гравця: 2-4 одиниці мінімум, 4-8 одиниць максимум
  • Висота: 3-5 одиниць над землею для фізичного падіння
  • Тестування колізій: Забезпечує приземлення припасів на твердих поверхнях

Інформаційні методи

get_enemies_remaining() -> int

Отримує кількість ворогів, які залишилися для спавну в поточній хвилі.

Повертає: Ціле число ворогів, які ще потрібно створити

get_current_wave_number() -> int

Отримує номер поточної хвилі (індексований з 0).

Повертає: Ціле число, що представляє індекс поточної хвилі

is_spawner_ready() -> bool

Перевіряє, чи готовий спавнер до роботи.

Повертає: true якщо спавнер ініціалізовано і готовий до спавну

SaveManager API

Примітка: SaveManager обробляє всі операції збереження стану гри, забезпечуючи надійну функціональність збереження/завантаження.

Огляд класу

class_name SaveManager extends Node # Система збереження та завантаження стану гри, яка обробляє # всі операції збереження, включаючи позицію гравця, # стани ворогів та дані рівня, використовуючи JSON формат.

Константи

SAVE_PATH: String
Шлях до файлу основного збереження гри в директорії користувацьких даних Godot.
Значення: "user://savegame.json"

Основні методи

save_game(player: Node, enemies: Array, level_seed: int = 0, level_settings: Dictionary = {}) -> bool

Зберігає поточний стан гри у файл.

Серіалізує дані гравця, позиції ворогів та стан гри в JSON файл. Обробляє перевірку помилок та забезпечує цілісність даних.

Параметри:

  • player: Node - Вузол гравця для збереження
  • enemies: Array - Масив вузлів ворогів для збереження
  • level_seed: int - Зерно, використане для генерації рівня
  • level_settings: Dictionary - Словник з конфігурацією рівня

Повертає: true якщо збереження успішне, false інакше

Структура збережених даних:

{ "player": { "position": [x, y, z], "health": 100, "ammo": 50, "level": 1 }, "enemies": [ { "position": [x, y, z], "health": 75, "type": "basic_enemy" } ], "level_data": { "seed": 12345, "settings": {...} }, "timestamp": 1640995200 }
load_game(player: Node, enemies: Array) -> Dictionary

Завантажує стан гри з файлу збереження.

Десеріалізує дані гри та застосовує їх до поточної сцени. Повертає дані рівня, які можуть бути використані для регенерації рівня.

Параметри:

  • player: Node - Вузол гравця для застосування завантажених даних
  • enemies: Array - Масив вузлів ворогів для оновлення

Повертає: Словник з даними рівня для регенерації

Обробка помилок:

  • Повертає порожній словник, якщо файл збереження не існує
  • Повертає порожній словник, якщо парсинг JSON не вдався
  • Логує помилки в консоль для відлагодження
  • Грацільно обробляє відсутні поля даних

Приклади використання

Базова операція збереження
var save_manager = SaveManager.new() var player = get_node("Player") var enemies = get_tree().get_nodes_in_group("enemies") var success = save_manager.save_game(player, enemies) if success: print("Гра збережена успішно!") else: print("Збереження не вдалося!")
Завантаження та застосування стану
var level_data = save_manager.load_game(player, enemies) if not level_data.is_empty(): # Застосувати дані рівня для регенерації того ж рівня if level_data.has("seed"): level_generator.set_seed(level_data.seed) if level_data.has("settings"): level_generator.apply_settings(level_data.settings) else: print("Дані збереження не знайдено, починаємо нову гру")

Архітектура системи

Ієрархія ігрових систем

GameManager (Центральний координатор) ├── Player (Контролер персонажа) ├── SaveManager (Система збереження) ├── DynamicLevelManager (Управління рівнями) │ ├── Navigation_Map (Просторові запити) │ └── LevelSpawner (Спавн ворогів) ├── GameUI (Користувацький інтерфейс) └── Camera3D (Відображення)

Відповідальності компонентів

GameManager
Центральна координація, обробка вводу, управління станом
SaveManager
Збереження стану гри, файлові операції I/O
LevelSpawner
Хвильовий спавн ворогів, прогресія складності
Navigation_Map
Просторові запити, пошук шляхів, виявлення колізій

Потік даних

  1. Обробка вводу: Ввід гравця → GameManager → Player
  2. Стан гри: GameManager ↔ SaveManager ↔ Файлова система
  3. Управління ворогами: LevelSpawner → Navigation_Map → ШІ ворога
  4. Оновлення UI: Ігрові події → GameManager → GameUI
  5. Генерація рівня: GameManager → DynamicLevelManager → Navigation_Map

Міркування щодо продуктивності

  • Запити дерева сцен: Мінімізовані через пошук на основі груп
  • Фізичні обчислення: Ефективний рейкастинг для позиціонування спавну
  • Управління пам'яттю: Автоматичне очищення переможених ворогів
  • Рендеринг UI: Розділення CanvasLayer для оптимальної продуктивності
